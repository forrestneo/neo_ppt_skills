# 测量驱动设计（蒸馏自 deck-dna / slide-skill / PPTAgent / NBLM2PPTX / AIPPT）

> 来源与许可：[deck-dna](https://github.com/opitaru-sys/deck-dna)、
> [slide-skill](https://github.com/icgma/slide-skill)、
> [PPTAgent](https://github.com/icip-cas/PPTAgent)、
> [NBLM2PPTX](https://github.com/laihenyi/NBLM2PPTX)、
> [AIPPT](https://github.com/LRriver/AIPPT)（各自仓库 LICENSE）。
> 核心信条（deck-dna 原话）：**"测量品味，而不是描述品味"**——所有设计参数
> 从被认可的参考稿里量出来，不许 AI 自己发明。定位：`style-extraction.md`
> 管"从参考图抽风格"，本篇管"从参考稿与渲染结果量出硬参数并闭环"。

## 一、参考稿 DNA：量五个字段（deck-dna）

喂 2-3 份"设计师做的、客户签过的"旧 PPT，产出一张 DNA 表后才许动手：

1. **Composition 构图**：图与文的相对位置——出血从哪边、分栏面板、图作背景纹理。
   （这是"看起来被设计过"与"看起来像模板"的最大单一差距。）
2. **Colors**：**用取色器从渲染像素取 hex，不信主题声明的 accent 色**——母版
   覆写经常导致声明色与实际用色不符。
3. **Fonts**：区分"文件里实际嵌入的"（解压查 ppt/fonts/）与"仅按名字引用的"——
   未嵌入字体在别人机器上会劣质替换。
4. **Recurring elements**：页脚、章节徽章、大数字 vs 小数字的呈现、bullet 样式、
   来源行格式与位置。
5. **Chaptering 章节节奏**：参考稿通常是"低密度分隔页 → 2-3 页数据页 → 循环"，
   连续数据墙读起来像电子表格。

## 二、字数预算校准：median 当硬上限（deck-dna）

- 脚本遍历参考稿每页统计词数，输出 mean/median/max + 最密 3 页（人工剔除离群）；
- **新稿每页字数硬上限 = median（略上取整），不取 mean**（离群页不抬高目标）；
- 构建后同一逻辑复检：超预算**砍内容或拆页，禁止缩字号塞字**——"缩字塞字是
  平模板的标志动作"（与我们 12pt 容量铁律同源，互为印证）。

## 三、展示级微规则包（deck-dna 实战评审产出）

- **28pt 以上展示字型手动控制每一处断行**，禁 autowrap；数字框 no-wrap 防溢出；
- QA 猎杀孤行（末行一个词）与行尾悬垂冠词——freelayout 已内建孤字防护；
- **hero 数字的单位字符降级**：%、x、$ 以数字的 50-60% 字号同基线紧贴末位——
  全尺寸单位像贴上去的；
- 图表：平涂、条上直接标数（无图例）、无网格线噪音、零基线比例准确、强调色只给
  焦点系列；
- 背景图方向性压暗（≈0.52 亮度）+ 指定侧渐隐，**不要软径向辉光**——渐变涂抹和
  淡斜纹是公认的 AI 稿签名；同一背景不跨页复用。

## 四、CJK 断行与字号测量（slide-skill / NBLM2PPTX）

- **避头尾（kinsoku）**：行首禁则字（，。、；：！？等）与行尾禁则字（《「【等）；
  修复策略宽度安全——优先标点上提至前行，放不下则前行末字下移；
- **数字+量词不可断簇**："6.5 小时"不能断成"6.5 小/时"（小时/分钟/公里/万元…量词表）；
- **孤行修复**：末行只剩 1-2 字 → 并上行或提前断点，修完再过一遍避头尾；
- **生成与 QA 共用同一宽度模型**（"wrapping model is intentionally the same
  approximation used by QA"）——两端模型不一致就会"检查说放得下、实际折三行"。
  freelayout 引擎已落地：`wrap_lines()`（避头尾+量词簇+孤行修复）供 fit_size 使用；
- **从渲染图反推字号（NBLM2PPTX 三信号，四层还原可用）**：墨迹高度不可靠
  （同字级"一二三"≈0.6em、"国"≈1.0em）；中文用 **em ≈ 行宽/全形字数**（实测
  误差 1.7%）；三信号信心值加权：行距（最稳 0.9）> 字宽（中文 0.55+0.45×全形占比）
  > 墨迹高度（0.25-0.6）。

## 五、规格冻结与长会话纪律（slide-skill）

- **Spec Lock**：设计规格（配色/字号/布局）冻结进 JSON 后全管线只读——防止 AI
  后续步骤"顺手改进"导致规格漂移；
- **每写一页前重读 spec**——长会话上下文压缩会让后面的页跑色、版式坍缩成重复图案；
- 跨页一致性需要单一作者持有全上下文，禁止子代理代写页面；
- QA 两查防呆：**节奏单调**（连续同密度页）与**版式多样性**（页面签名去重）——
  我们的 visual_gate 已有前者的雏形（三连同版式），后者可作 md5 指纹扩展。

## 六、证据链门禁（PPTAgent）

- **哈希证据链**：对每页源文件+共享资源算 sha256；渲染与评审记录绑定输入哈希——
  **改了源而不重渲染/重评审，build 与 finalize 直接拒绝**（机制化防止"没看就交"，
  与我们 audit-protocol 的"报告先删后写 + mtime 新鲜度"同源，粒度更细到页级哈希）；
- **deck 级联络表评审**：LibreOffice→PDF→**4 页一张 2×2 联络表（带页码角标）**，
  查整套一致性/叙事流/视觉离群页——整 deck 交叉审查的最便宜实现；
- **结构化评审 schema**：verdict ∈ pass/fail/unjudgeable；每条 issue 必带
  severity+页号+描述+修法；**带 blocker/major 的 pass 判为非法评审**。

## 七、生成式重建的合并策略（AIPPT）

- **自有元数据 ⊕ OCR 几何**：文本内容用生成端已知原文（零 OCR 错字），位置字号
  用视觉测量——我们 imagegen 出的页天然带元数据，做 B 层还原时这是零成本质量跃升；
- **保守形状拟合**：高置信（≥0.9）简单几何才转原生形状，**拿不准的一律留位图，
  宁缺勿错**；
- **fallback 显式声明**：降级路径必须在响应头/交付说明声明，不许静默
  （与 `audit-protocol.md` 三态语义同源）。

## 八、执行顺序

1. 有参考稿 → 先量 DNA 五字段 + median 词数上限（第一、二节），产出 DNA 表；
2. 无参考稿但指定风格 → 按 `style-dimensions.md` 四维组合 + STYLE_INSTRUCTIONS 块；
3. 写稿时开 spec 锁（第五节），每 2-3 页重读规格；
4. 出稿过 `layout_audit.py` + `visual_gate.py`，deck 级用联络表（第六节）交叉审；
5. 涉及从渲染图/截图取字号时用三信号法（第四节）。
