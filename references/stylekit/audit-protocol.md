# 验收协议：静态门 → 视觉门 → 证据链（蒸馏自 6 个引擎的质检体系）

> 来源与许可：PTT-Studio（MIT）、pptwise（MIT）、dsh-ppt（MIT）、dsh-ppt-maker（MIT）、
> PPT-Design-Skill（MIT）、dsh-office-tools（MIT）、deepseek-design（Source Available，仅学习思想）。
> 定位：`layout-engine.md` 第二节的阈值表是"单条规则"，本篇是**完整验收流程**——
> 查什么、按什么顺序、过不了怎么办、怎么对用户诚实。

## 一、分层验证语义（先把"完成"说清楚）

dsh-ppt 三态口径，防止 AI 谎报完成：

| 层 | 状态 | 含义 |
|---|---|---|
| 静态估算 | `static: checked` | layout_audit.py 等不渲染检查通过 |
| 渲染成功 | `pptxRender: rendered` | LibreOffice 出了 PNG/PDF，含源文件 sha256 收据 |
| 视觉验收 | `visual: not-verified` 直到人/视觉模型看过 | **静态通过 ≠ 视觉验收**，永远分开陈述 |

交付说明里三态都要写；缺字体、未做视觉检查必须显式声明，不能声称"已验收"。

## 二、静态几何门（阈值全集，先跑这个）

`layout_audit.py` 已实现：越界（error）、占位符（error）、悬空图片关系（error）、
重叠 >10%（warning）、估算溢出 >105%（warning）、latin 无 ea（warning）。
引擎界更严的全集（纳入自查与后续脚本升级）：

| 检查 | 阈值 | 级别 |
|---|---|---|
| 内容重叠 | >较小盒 **5%**（内容元素间；装饰另查压字） | error |
| 装饰压字 | 装饰在上层 ∩ 文字框 >**4%** | error |
| 文字溢出 | 横/纵向 ≥**4px** 或软换行多 ≥**2 行** | blocker |
| 孤字行 | 末行仅 1 个 CJK 字（或 1–3 字符短词） | 修排版 |
| 对比度 | 正文 **4.5:1**、大字（≥24px/18pt+）**3:1**、meta 层 3:1 不限字号 | <4.5 warning、<3 blocker |
| 图片分辨率 | 图宽 < 盒子宽×100px | warning |
| 表格密度 | >6 列（字号降 14pt）／格 >18 units | warning |
| 图表密度 | 类目 >10／折线 >8 系列 | warning |
| 覆盖率 | 低于密度档下限（25/35/45/55/60%，`overflow-and-density.md` 第五节） | warning |
| 节奏单调 | ≥3 连续页同 lead 组件 | warning |
| 拥挤列 | 同排异列文字间隙 <1.25em | warning |

## 三、中文排版 fit 红线（deepseek-design 验收标准，可机械判定）

1. 中文标题必须 balance 换行（均衡断行，避免前行长后行短悬殊）；
2. **末行只剩"一个字+标点" = fit 失败**——即使包围盒没溢出；
3. 修复 = 重排行宽或删非必要措辞；**不许缩全部正文字号、不许丢事实**；
4. 标题与首个内容块之间必须保留可见空隙；
5. 所有页在同一画布尺寸下对比检查。

## 四、视觉门协议（渲染后的复核闭环，PTT-Studio 全流程）

1. **渲染**：LibreOffice → PNG（96dpi 起步，逐页）；
2. **逐页单独送视觉模型**（不整卷一起判）：temperature=0，判定角色
   "senior presentation design reviewer, review rendered slides at projection size"，
   只判图上可见的东西，严格但务实；七项清单：文字溢出裁切 / 元素重叠 / 对比可读 /
   层级 / 对齐边距 / 装饰穿字 / 图片质量与密度留白；
3. **强制 JSON 结论**：`{"verdict":"pass|warn|fail","score":0-100,` `"issues":[{severity,area,issue,fix}]}`；
   severity 口径：**error = 观众无法读到内容；warning = 打磨问题；info = 建议**；
4. **修正循环**：改稿→重组→重渲染→重审，**最多 3 轮**，超限如实告知用户；
5. **修正优先级五级**：内容错误 > 文字溢出遮挡 > 图内文字乱码 > 风格不一致 >
   对齐间距。原则：**改文字优先于改字号；改字号不得低于最小字号；图片问题只重生成
   那一张**；
6. **降级路径**：无独立视觉模型时——会话模型自己读 PNG 按清单查；连读图都做不到
   则跳过并在交付时**声明"视觉检查未做"**。

## 五、双门审查（PPT-Design-Skill，内容级终审）

- **Gate 1 视觉门（先看）**：client-ready 第一眼？每页有强视觉锚点、第一读、完整
  takeaway？风格方向一致？密度/留白有意图？——**技术上正确但视觉平庸 = 打回**，
  即使零重叠零溢出。
- **Gate 2 缺陷门（逐条对证据）**：对照需求逐条查——溢出/裁切/遮挡、16:9 投影
  可读性、图表图示可读性、配色字体一致性、图片裁切与色调一致。
- **验收状态机**：`PASS` / `NEEDS_REVISION`（有明确可修复问题）/ `BLOCKED`（缺证据
  或渲染失败）。"文件生成成功"≠ 视觉通过。

## 六、验收合同（需求不丢失，PPT-Design-Skill 模板）

把口头需求固化为表格，交付前逐条对：

```
| # | 需求 | MUST/SHOULD/NICE | PNG 可见证据 | 状态 |
|---|------|------------------|--------------|------|
| R1 | （用户原话/转写） | MUST | 第 N 页 ××× | PASS |
```

- MUST 未清零不得交付；"数学正确但违反合同"的内容也要删；
- 参数审计（decidedBy）：brief 里每项参数记录是用户定的还是助手替定的，
  交付时说明——替用户做的设计决策必须可见。

## 七、无渲染环境的自检回路

- **ASCII 线框"模型之眼"**（dsh-office-tools）：把每页元素按坐标画成 64×18 字符
  网格线框（`+--+` 画框、框内首行放文本前 10 字、图片标 IMG）——生成回显落点 +
  读回实际几何，两边同构，无渲染器也能核对重叠/越界/比例失衡。
- **常见返工清单**（生成前自检 + 交付前再过）：
  时间线节点间距按画布反推（13.33 in 画布 4 节点 ≈ 3.1 in，别超安全区）；
  浅色文字配白卡 = 不可读（补 card/border token）；卡片铺到内容区边界（x6–94%）；
  面板不透明度 ≥0.95；同一页不超 2 个字体、3 个颜色家族。

## 八、消费者契约（"自己写自己读通过"不算数）

- 自己的审计器 + 自己的读回器互检通过，**不能证明真实 PowerPoint/WPS 接受**——
  ZIP 条目间隙宽容读取器会放过、严格消费者会拒绝。最终验证至少一次
  LibreOffice（或真实 Office）开包渲染。
- **能力显式声明，拒绝优于损坏**（dsh-office-tools 设计原则）：做不了无损修改就
  明说（"不能只因一个库支持创建，就宣称能无损修改任意 Office 文件"）；
  缺能力返回明确原因，**不要悄悄把嵌入改成链接、把失败标成成功**。
- 修改/删除源文件后渲染收据即失效；重渲染才能再声称"渲染已验收"。
